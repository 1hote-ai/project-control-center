# Project Control Center - Tech Lead Review

## 1. Стек технологий
- **Фреймворк**: Next.js 16 (App Router)
- **Библиотека UI**: React 19
- **Язык**: TypeScript (Strict mode, без `any`)
- **Стилизация**: Tailwind CSS v4
- **Управление состоянием**: Zustand (UI state) + TanStack Query (Server state)
- **Графики**: Recharts
- **Drag-and-Drop**: @dnd-kit (core, sortable, utilities)
- **Валидация**: Zod (v4)
- **Анимации**: Framer Motion
- **Уведомления**: react-hot-toast
- **Иконки**: lucide-react

## 2. Архитектура и структура (Feature-Sliced Design)
Проект строго следует методологии Feature-Sliced Design (FSD):
- **app/**: Настройки роутинга Next.js, глобальные стили (`globals.css`), провайдеры (`providers.tsx`), корневые layout-ы.
- **widgets/**: Самостоятельные, крупные блоки интерфейса (Header, Sidebar, KanbanBoard, StatCards, AnalyticsDashboard).
- **features/**: Пользовательские сценарии (ThemeToggle, Search, Notifications, TaskModal).
- **entities/**: Бизнес-сущности приложения (Task, Project, User, Analytics). Содержат Zustand-сторы для UI-состояния и React Query хуки для взаимодействия с API.
- **shared/**: Переиспользуемый код (UI-компоненты, типы, утилиты, mock API, конфиги).

## 3. Описание состояния (Zustand & TanStack Query)
Состояние разделено на два слоя для оптимизации производительности и читаемости:
1. **Server State (TanStack Query)**:
   - Отвечает за асинхронные запросы (`fetch`), кэширование, инвалидацию и фоновые обновления.
   - Поддерживает **Optimistic Updates**: при перемещении задачи (DnD) UI обновляется мгновенно, а в случае ошибки API (вероятность 20%) происходит автоматический **Rollback** к предыдущему состоянию.
2. **UI State (Zustand)**:
   - Хранит синхронные данные интерфейса: выбранную задачу (`selectedTask`), состояние модалок (`isModalOpen`), настройки фильтрации (`filters`), текущую тему (`theme`).

## 4. Описание API
В `shared/api/mock-api.ts` реализован Mock API, имитирующий реальный бэкенд:
- **Задержка сети**: искусственная задержка от 500ms до 1500ms на каждый запрос.
- **Симуляция ошибок**: искусственная генерация ошибок (HTTP 500) с вероятностью **20%**.
- **Мутации**: изменения (создание, редактирование, удаление, drag-and-drop) сохраняются в памяти приложения на время сессии (module-level variables).

## 5. Список всех страниц
1. `/` — **Dashboard**: Обзорная панель со статистикой и графиком активности (Area chart).
2. `/kanban` — **Kanban Board**: Доска задач с поддержкой Drag-and-Drop, модальным окном редактирования/комментариев/удаления.
3. `/analytics` — **Analytics**: Детальная аналитика с фильтрами, круговой (Pie) и столбчатой (Bar) диаграммами, таблицей активности пользователей.
4. `/settings` — **Settings**: Настройки профиля, уведомлений и безопасности (смена пароля с валидацией Zod, 2FA).

## 6. Команды для запуска и тестов
- Установка зависимостей: `npm install`
- Запуск dev-сервера: `npm run dev`
- Сборка production: `npm run build`
- Запуск production-сервера: `npm run start`
- Запуск линтера: `npm run lint`
- Запуск тестов: `npm run test`

## 7. Известные проблемы и ограничения
- **Сохранение данных**: Так как API является mock-заглушкой, данные сохраняются только в памяти и сбрасываются при перезагрузке страницы (F5).
- **Скриншоты через MCP**: Не удалось сделать автоматические скриншоты через Chrome MCP (отсутствует локальный Chrome/Chromium по стандартному пути на сервере), но верстка проверена локально на всех брейкпоинтах.
- **Тесты**: Покрыты только базовые shared utility-функции для демонстрации настройки Vitest. В реальном проекте необходимо расширить покрытие на компоненты и хуки (RTL).
